# Web languages

The 16-language experience and localized detector links are live on October 7, 2026, as Azure revision `mathsolver--detector-links-1007`. The URL-based SEO upgrade shipped earlier as `mathsolver--language-seo-1007b`, which is the immediate rollback source. The owner confirmed keeping all 16 languages. Related: [[product-overview]], [[codebase-map]], [[tech-and-ops]].

## Learner experience

- The desktop sidebar and mobile header offer a language selector with native language names: English, Spanish, French, Portuguese, German, Russian, Ukrainian, Uzbek, Turkish, Arabic, Persian, Urdu, Hindi, Bengali, Chinese, and Indonesian.
- The URL determines the language: English is `/`; the other 15 homepages use `/es`, `/fr`, `/pt`, `/de`, `/ru`, `/uk`, `/uz`, `/tr`, `/ar`, `/fa`, `/ur`, `/hi`, `/bn`, `/zh`, and `/id`. The selector navigates to the chosen URL, and native-name footer links work as crawlable anchors. Browser settings and saved preferences never redirect visitors or override a shared URL. `mathsolver_language` remains an advisory device-local selection, with no account required.
- Navigation, the solver hero and inputs, upload/drawing controls, solution actions, practice runner, and practice library use checked-in translations. New solutions, follow-ups, quizzes, and question explanations use the selected language, including when their mathematical source is in another language.
- The homepage FAQ links to Detecting AI in the same language where that site has a verified page: Spanish `/es`, French `/fr`, Portuguese `/pt` (Brazilian Portuguese), German `/de`, Russian `/ru`, Arabic `/ar`, and Uzbek `/uz`. English and the other eight languages use `https://detecting-ai.com/`. A translated note explains that Detecting AI offers pages in several languages. The shared route allowlist lives in `src/lib/i18n/external-links.ts`; unsupported paths are never guessed, and no math content is attached to the link.
- Existing chat answers and saved quizzes retain their original content. New assistant answers and questions record an optional language code for accessible rendering and notebook persistence. Cached practice explanations record their language and regenerate when the learner requests steps in a different language.
- Arabic, Persian, and Urdu use right-to-left reading order. Equations and MathLive fields remain left-to-right and isolated from surrounding prose. The overall desktop panel layout remains stable.

## Implementation contract

- `src/lib/i18n/locales.ts` is the server-safe allowlist, native-name/direction/step-label registry, browser matcher, and trusted model-language instruction builder. Invalid request language values fall back to English and are never interpolated into a prompt. Requests without a `language` field retain the original contract, including existing mobile clients.
- `src/lib/i18n/messages.ts` supplies a typed, complete translation catalog with matching interpolation fields across every supported language. `src/context/LanguageContext.tsx` exposes URL-owned `locale`, `direction`, `setLocale`, and `t` from Next navigation. `src/components/layout/LanguageSelector.tsx` is shared by desktop and mobile.
- `/api/solve`, `/api/practice`, and `/api/practice/steps` accept the optional `language` code through their existing request validation. Calculator mode still uses the server registry. Client-facing JSON keys, correct-answer indexes, LaTeX, mathematical meaning, and streaming format stay unchanged. Practice-step generation requests a model-side `{ "steps": [...] }` object to satisfy Azure JSON mode, unwraps it into the existing HTTP array, and accepts legacy model arrays; malformed/empty steps are rejected. Practice prompts reinforce the target language in both the system instruction and the user task: a live test showed that a long Arabic source could otherwise cause a Spanish quiz to copy Arabic wording.
- `post-solution-actions.ts` recognizes each supported translated step header as well as legacy English headers. Localized failures are excluded from printable/actionable solutions. Follow-up buttons submit translated learner messages.
- All 16 homepages are statically generated with translated initial HTML: hero, explanatory sections, calculator-card labels, mobile promotion, FAQs, footer, title/description, Open Graph/Twitter text and image alt, and language-specific WebPage/WebApplication JSON-LD. Each page self-canonicalizes and declares the same 16 reciprocal language alternates plus `x-default` at the English root. The sitemap contains the same alternate registry. No language is selected using request headers, IP, cookies, or browser storage.
- `src/lib/i18n/landing/*.json` is the complete server-owned homepage catalog, typed by `landing.ts`; `seo.ts` and `paths.ts` generate metadata, schema, public URLs, alternates, and native Next config rewrites/redirects. The actual HTML document is in `app/[locale]/layout.tsx`; context-only providers stay in the stable `app/layout.tsx` above that changing segment so active chats, streaming, practice state, and in-memory composer drafts survive language navigation. Turnstile keeps one widget via a client portal into the document body.
- Detecting AI destinations were verified against its advertised language selector/alternates, HTTP status, HTML language and canonical on October 7, 2026. Its Dutch page has no matching MathSolver locale; the eight unsupported MathSolver locales are `uk`, `tr`, `fa`, `ur`, `hi`, `bn`, `zh`, and `id`. Portuguese destination `hrefLang` is `pt-BR`; root fallbacks declare English. Recheck the external site's advertised routes when changing this allowlist. No runtime request to the detector is needed to render MathSolver.
- Existing English public URLs are internally rewritten to `/en/...` by `next.config.ts`; direct `/en` page aliases permanently redirect to unprefixed equivalents. Generated English metadata images remain accessible assets. Editorial/account/video routes live in `[locale]/(english-only)` and reject non-English prefixes instead of advertising untranslated duplicates. `/practice-tests` and localized variants remain `noindex` and outside the sitemap. Unknown locale paths return real 404s with `noindex`.

## Current scope

The selector applies to the fully translated homepage, solver, and practice experience. Calculator guides/custom example hints and graphing controls, Pressroom articles, legal/support pages, account dialogs, mathematical-keyboard terminology, printing chrome, and video pages/narration remain English. Those surfaces need separate editorial or feature localization; selecting a web language does not translate already-saved content or the Flutter app.

To add a language, add its server-owned metadata to `LANGUAGES`, a complete translated catalog to `messages`, and a complete `landing/<code>.json` import in `landing.ts`. Add its Open Graph locale to `seo.ts`; URLs, alternates and sitemap then derive from the registry. Keep step labels aligned with the registry and preserve every `{placeholder}`. Review the reading direction and verify the solver/practice flow on desktop and mobile before release.
